# 実装と確認

確認日: 2026-10-22

.NET 10 / WPF で実装。`src/MangaViewer` がアプリ本体、`tests/MangaViewer.Checks` が機能チェック。`artifacts/app/MangaViewer.exe` が実行ファイル。

## 確認済み

- Release ビルドと publish が成功。
- 自動チェックで自然順での画像抽出、ZIP とフォルダからの同一ピクセルの読み込み、デコード済みキャッシュ、ページ境界、各キー、ホイール、方向設定、単ページ切り替え、シーク、全画面、破損 ZIP、設定保存と復元を確認。
- 未読み込みページへの移動時にシークバーだけが先行する不具合を再現して修正。画像・ページ番号・シーク位置の同時更新、連続シークの最新位置、長押し中の実際の画像ピクセルとシーク位置の一致を回帰チェックに追加。
- WPF の画面を画像出力し、Figma の色・タイトルバー内の操作ボタン・ページ面積・シークボックスを比較。全画面アイコンの余白による欠けを修正。
- デスクトップ上でもアプリを起動。Ctrl + O で検証 ZIP を開き、中央クリックでシークバーが出ること、左クリックで 1–2 から 3–4 ページへ進むこと、再度中央をクリックするとバーが隠れることを確認。
- シークバー上のホイール操作が読書領域へ伝わる不具合を修正し、回帰チェックを追加。

## 性能の測定範囲

600 × 900 の PNG 12 枚を ZIP にした検証用データで、ページ要求から WPF の描画優先度の処理までの時間を 8 回測定。確認時は約 0.7〜5.2 ms。値はキャッシュと先読みを含む表示処理の測定であり、物理ディスプレイ上の入力遅延を測ったものではない。

実際の漫画アーカイブや高解像度画像、ネットワークドライブでの性能は未測定。D&D はウィンドウ全体で受け付けるコードを実装したが、Explorer からの実ドラッグ操作は今回の自動チェックには含めていない。

## 対応範囲

PNG・JPEG・BMP・GIF・TIFF の画像、ZIP・CBZ・PDF、画像フォルダに対応。暗号化 ZIP、パスワードが必要な PDF、WebP・AVIF は未対応。ファイル関連付けは追加していない。

## PDF (2026-10-25)

Windows.Data.Pdf によるページ描画を既存の先読み・画像キャッシュへ接続した。ドラッグ＆ドロップの受け付けと Ctrl + O の選択対象にも PDF を追加した。[描画サイズの指定は DIPs](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpagerenderoptions.destinationwidth) のため、表示倍率に依存せずキャッシュ画像を最大幅 4096・高さ 2160 ピクセルに収める。

縦長・横長を混ぜた 7 ページの PDF を生成し、ページ数・描画内容・前後の移動・単ページと見開き・サムネイルの再利用と更新・履歴からの再表示・破損 PDF の拒否と表示中作品の保持を確認した。既存の ZIP・フォルダの検証を含め 228 項目が成功。実 WPF ウィンドウの画像は `artifacts/checks/pdf-reading.png` に出力した。Explorer からの実ドラッグ操作とパスワード付き PDF は未検証。

単色図形の検証用 PDF では、未キャッシュの描画に約 70〜171 ms、キャッシュからの取得は表示精度 0.01 ms 未満だった。記録は `artifacts/checks/pdf-timings.txt`。画像を多く含む実際の漫画 PDF の性能を保証する測定ではない。

## インストーラー

Inno Setup 6.7.3 と .NET SDK 10.0.402 で `artifacts/installer/MangaViewer-Setup.exe`（0.1.0）を生成した。セットアップに含める win-x64 の publish 出力も、デスクトップ上で起動して開始画面の表示と正常終了を確認した。

Program Files へのインストールを実行したが、Windows の管理者承認が取り消され、セットアップは開始されなかった。インストール先のファイル配置、スタートメニュー登録、上書き更新、ピン留めからの起動は未確認。管理者承認後に確認する。
