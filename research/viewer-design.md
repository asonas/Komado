# 漫画ビューワーの調査と初案

確認日: 2026-10-22

## 一次情報

[NeeView 公式](https://neelabo.github.io/NeeView/en-us/) は、フォルダ・圧縮ファイルの閲覧、ZIP 対応、見開き、全画面、キー設定を案内している。今回の必須要件と近い Windows 向けビューワーであり、読書を補助する操作の参考にした。

[SumatraPDF の Comics and manga](https://www.sumatrapdfreader.org/docs/Comics-and-manga) では、画像フォルダと ZIP を含むアーカイブ、単ページ・見開き、右から左への読書、左右端のクリックによるページ送りを説明している。漫画モードでは左キーで進み、右キーで戻る。方向設定を見開きの順序と入力操作の両方に反映する考え方を参考にした。

## 今回の設計判断

| 項目 | 判断 |
| --- | --- |
| ZIP とフォルダ | 「開く」ボタンは置かず、ZIP と解凍済みフォルダをウィンドウ全体へドロップして開ける。読書中も受け付ける |
| 高速なページ送り | ページ遷移は即時切り替え。先読みとデコード済みキャッシュは実装候補であり、測定前に性能を断定しない |
| 左右の変更 | 元の送り方向ボタンをタイトルバーへ移し、「左で次へ」「右で次へ」を選べるようにする |
| 単ページ・見開き | 小さな切り替えに集約。見開きではページ番号も 2 ページ分表示する |
| 全画面 | 読書に集中する補助操作として置く |
| 拡張機能 | 本棚、タグ、クラウド同期、動画・PDF 対応は今回の範囲に含めない |

## 実装時に確かめること

高速性は Figma では検証できない。対象 PC、画像サイズ、圧縮サイズを記録し、初回表示時間と連続ページ送り時の入力から描画までの時間を測定する。隣接ページの先読みは候補とし、メモリ消費とあわせて判断する。

ファイル名の自然順 (1、2、10) と画像以外の除外は読み込み時の基本動作として確認する。ZIP 内のフォルダや暗号化 ZIP の対応範囲は、実装開始時に決める。
